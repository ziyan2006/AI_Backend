# 缺积木 LLM 状态提示设计

## 目标

将“输入/输出积木不足”从本地硬拦截改为 LLM 交互状态。即使电路为空，用户询问“你是谁”时也必须走完整 LLM 调用，由模型先回答问题，再以自然、儿童友好的方式提醒需要补齐哪些输入/输出积木。

## 状态机

根据关卡要求与已识别、`id_valid` 的积木数量计算：

| 状态 | 条件 |
| --- | --- |
| `READY` | 输入和输出均满足关卡要求 |
| `MISSING_INPUT` | 仅输入积木不足 |
| `MISSING_OUTPUT` | 仅输出积木不足 |
| `MISSING_INPUT_OUTPUT` | 输入和输出均不足 |

状态同时携带各自的缺失数量，避免将数量散落在提示词拼接逻辑中。

## LLM 提示策略

非 `READY` 状态会在正常系统提示后增加一条动态系统消息，内容包含：

- 当前缺少的输入和/或输出积木数量；
- 必须先正常回答用户刚刚的问题；
- 必须在同一回复中自然提醒玩家补齐缺少的积木；
- 未补齐时不指导具体接线；
- 不规定最终提醒话术，保持模型表达自然。

`READY` 不注入该消息。电路信息、关卡目标、端口映射仍按既有路径提供给模型。

## 调用行为

- 删除“缺积木即直接返回本地兜底文本”的决策分支。
- 只要 LLM 配置可用，四种状态均调用一次 LLM。
- 不追加固定提醒，不检查或改写模型首答，也不进行第二次 LLM 调用。
- 缺少 API Key 等配置错误仍按既有错误路径处理，不伪造模型回复。

## 验收标准

1. 空电路且关卡要求输入、输出时，`decide()` 调用 LLM 一次而非返回本地兜底。
2. 模型收到的消息包含动态缺失状态和准确的缺失数量。
3. 模型的原始回答被直接返回，不被服务端追加固定文本。
4. 积木齐全时不发送缺积木状态提示。
5. 现有电路上下文、工具调用与 LLM 错误日志行为保持不变。

## 范围

变更限制在 `openai_compatible.py` 和其测试；不改动固件快照协议、前端模拟器或 WebSocket 协议。
