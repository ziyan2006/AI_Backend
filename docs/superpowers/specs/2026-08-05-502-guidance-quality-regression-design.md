# 502 多轮引导质量回归设计

## 目标

把 502 关刚完成的六轮真实测试固化为评测器预设，并修复测试暴露出的目标说明过于模糊、求助与检查意图未识别、错误直连缺少稳定诊断、工具语音过于固定的问题。

## 测试预设

新增名为 `502-guidance-quality` 的多轮预设，仍使用统一的 `tuco_conversation_scenario_v1` 数据结构。六轮依次提供完整 `tuco_circuit_v2` 快照：

1. 空板询问关卡目标。
2. 已放好三块输入和一块输出，询问下一步。
3. 三组两两与门已完成，主动求助。
4. 一块与门错误直连最终输出，要求检查。
5. 保持错误快照，追问为什么。
6. 拆线并放好或门、接入一路结果，继续询问下一步。

CLI 增加可重复的 `--conversation-preset`，可以与 `--conversation-scenario` 合并运行；场景之间并发、单场景内部串行、完整 trace 和报告格式保持不变。

## 意图设计

在现有四种意图之外增加：

- `提示求助`：覆盖“给我一点提示”“我不会了”“卡住了”等表达。运行语义规划获取可靠的下一步事实，但默认不提供工具，提示词要求模型只给一个启发式问题或轻提示。
- `检查诊断`：覆盖“接对了吗”“哪里有问题”“为什么不亮”等表达。运行真值表诊断并把明确的问题事实注入模型；默认不亮灯，除非用户明确要求高亮。

`开始行动` 仍保持严格的候选工具选择，避免求助模式重新变得过度积极。

## 通用诊断

新增独立电路诊断模块，复用 `build_circuit_graph` 与 `simulate`：

- 保留物理无效边、重复输入源和环路诊断。
- 当最终输出已有来源但真值表状态为 `wrong` 时，定位直接驱动输出的源积木和连线。
- 生成儿童可理解但不包含端口号、槽位号的事实，例如“最终输出现在直接来自一块与门，它只覆盖部分输入情况，这条线不能作为完整答案”。
- 对明确的下一步请求，错误输出连线优先转换成 `DisconnectPortsAction`，防止规划器绕过错误继续堆积木。

该诊断只依据关卡真值表和当前完整快照，不写死 502 的积木数量或特定端口。

## 回复质量

- 缺少输入输出时，提示词要求直接说出缺少数量，不再反问儿童“还缺什么”。
- 关卡目标类问题必须包含核心判定条件，不能只说“判断几个开关”。
- 工具调用没有模型文字时，使用快照中的源积木和目标积木生成确定性语音；例如“把亮起的与门输出接到或门输入”。不增加第二次模型请求，避免额外延迟与失败率。

## 验收标准

- 预设能通过 CLI 选择并输出六轮完整报告。
- “给我一点提示”被识别为 `提示求助`，有语义计划事实但无强制工具调用。
- “我这样接对了吗”被识别为 `检查诊断`，回复明确指出错误直连。
- 错误快照下询问“下一步”时，首个安全候选是拆线。
- 空板回答包含“至少两个输入为 1”以及缺少的准确输入输出数量。
- 工具语音包含源/目标积木名称且每次仍只操作一对端口或一个槽位。
