# 可靠动作降级与关卡事实引导设计

## 背景

`circuit-v2` 已能让模型从后端生成的安全候选中选择动作，但最近的多轮并发评测仍暴露出以下问题：

- 模型正确选择拆线候选，最终归一化却把已连接端口判为不可用，导致工具被删除。
- 物理角色错误的真实连线只生成文字诊断，没有进入拆线候选，后续连接候选又被占用端口阻断。
- 动作映射失败时返回“我先确认一下”等空洞兜底，没有告诉孩子应检查什么。
- 301、403、601 的固定教学素材有时压过实时快照事实，出现过早报出门名称或错误描述已有积木作用的问题。

典型 Trace：

- 502 第 5 轮选择 `rev32-action-1`，候选要求拆除 `16 -> 2`，真实快照中该边存在，但 `tool_mapped=false`。
- 403 第 5 轮存在 `0 -> 48` 的错误角色连线，诊断指出“没有从输出接到输入”，但 `disconnect_edges=[]`，规划器继续建议使用已被占用的端口 0。
- 601 将与门描述为“汇总结果”，与选择器电路中与门负责条件筛选、或门负责汇总的实时语义冲突。

## 目标

- 连接和断线动作采用不同的端口占用校验。
- 可定位到真实边的物理角色错误必须生成拆线候选。
- 候选无法安全映射时，返回基于候选事实的明确文字提示，不执行未经验证的动作。
- 存在实时电路进度时，诊断事实和规划事实优先于关卡固定教学素材。
- 301、403、502、601 获得稳定的回归覆盖和多轮并发验证。

## 非目标

- 不增加第二次 LLM 路由调用。
- 不允许模型直接生成端口、槽位或积木参数。
- 不自动选择第一条候选作为兜底动作。
- 不放宽拓扑版本、端口方向、端口占用和解锁积木安全网。
- 不在本轮修改固件、云端部署或关卡真值表。

## 设计

### 1. 按动作意图区分端口校验

`highlight_ports` 的合法性取决于 `intent`：

- `connect`：输出端和输入端都必须存在、方向正确，并且尚未被现有边占用。
- `disconnect`：指定的两个端口必须组成当前快照中的真实边；端口已连接是必要条件，不是拒绝条件。

归一化只负责最后一道安全校验，不得把语义网关已经映射成功的真实拆线动作误删。

### 2. 物理错误边进入拆线诊断

诊断器检查每条真实边的端口角色。只要边没有形成“输出端到输入端”的合法组合，就同时生成可朗读的诊断事实，并把规范化后的真实端口对加入 `disconnect_edges`。规划器优先把这类边转换为拆线候选，避免继续使用已被错误边占用的端口生成连接候选。

### 3. Grounded fallback

动作候选解析成功但无法映射或最终校验失败时，不返回泛化占位句。降级文案由候选动作类型和 `child_facts` 生成：

- 拆线：指出当前连接需要调整，并要求先拆掉这条线。
- 连线：指出该连接暂时不能安全亮灯，并引导检查空闲输入端。
- 摆放：指出槽位状态可能已变化，并引导寻找真正空槽位。

如果候选包含可靠的 `child_facts`，第一句优先使用其中最具体、最短的一条；第二句只给一个动作。降级结果不得包含工具调用。

### 4. 实时语义事实优先

当 `has_actionable_circuit_progress=True` 时：

- 当前诊断、可靠提示依据和候选事实是回答当前状态的第一依据。
- 关卡专用素材只可补充概念，不得指定下一块积木、固定接线顺序或猜测已有积木作用。
- 301 先描述“两个输入都满足才输出”的行为，再按需引入门名称。
- 403 先区分“个位结果”和“进位”，再结合当前快照解释已有积木。
- 601 使用“控制信号选择 A 或 B 哪一路通过”的主线；与门只能描述为筛选条件，或门才可描述为汇总。

冷启动且没有可用进度时，仍可使用关卡的开场和行动专项素材。

## 安全边界

- 工具参数仍完全来自 `SemanticActionGateway`。
- 候选编号、拓扑版本和真实边必须一致。
- 降级文案不执行硬件动作。
- 模型输出不能绕过最终归一化校验。

## 验收标准

- 已连接端口上的真实 `disconnect` 工具保留。
- 同样端口上的新 `connect` 工具仍被拒绝。
- 403 的错误角色边生成拆线候选。
- 候选映射失败时不再出现“我先确认一下”或“再问我一次”，且 `tool_call` 为空。
- 601 有实时进度时不再把与门描述为汇总结果。
- 301、403 首次介绍遵循“先白话目标，后术语”。
- 相关单元测试、全量测试、Ruff 和 `git diff --check` 通过。
- 多轮并发评测中 403、502 的执行轮能映射拆线动作，601 不再出现语义冲突；上游 `ReadError` 单独记录。
