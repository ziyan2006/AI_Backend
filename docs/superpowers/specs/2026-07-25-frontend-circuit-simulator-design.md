# 前端电路测试台模拟器设计

## 状态

- 日期：2026-07-25
- 决策：采用方案 A（DOM 实物面板 + SVG 连线层）。
- 范围：将现有前端测试台的抽象 64 点端口预览改造成可编辑的虚拟电路面板；不改动固件或后端协议。
- 实施：已完成；空槽序列化已与固件保持一致。

## 目标

测试人员能在浏览器中把虚拟积木拖入真实 4×4 槽位、按端口连接导线，并让 HTTP 决策请求和已经建立的 WebSocket 会话始终使用当前的 `CircuitSnapshot`。

模拟器必须服从嵌入式端的积木、槽位、端口方向和快照序列化规则，避免浏览器测试数据与实机上报数据出现语义偏差。

## 已核验的固件契约

固件源码位于 `E:\emb_agent\main`。可定义的积木为：

| 固件 `component` | 显示名称 | EEPROM 标识 |
| --- | --- | --- |
| `input` | 输入积木 | `0xF0` |
| `output` | 输出积木 | `0xF1` |
| `not_gate` | 非门积木 | `4` |
| `and_gate` | 与门积木 | `5` |
| `or_gate` | 或门积木 | `6` |
| `nand_gate` | 与非门积木 | `7` |
| `nor_gate` | 或非门积木 | `8` |
| `xor_gate` | 异或门积木 | `9` |
| `xnor_gate` | 同或门积木 | `10` |

`NULL` 仅表示无法识别或空状态，不是可拖放积木。

端口角色按屏幕视觉方向确定：

- 输入积木：上、右、下、左四侧均为输出。
- 输出积木：仅左侧为输入，其他侧未使用。
- 非门积木：左侧为输入，右侧为输出，上下侧未使用。
- 与、或、与非、或非、异或、同或：上、下为输入，右侧为输出，左侧未使用。

## 物理槽位与端口映射

面板保留用户确认的 4×4 实物布局。可视标签采用“底板模块-级联槽位”；程序内部槽位采用与固件一致的零基软件槽位 `0–15`：

| 行 | 左一 | 左二 | 左三 | 左四 |
| --- | --- | --- | --- | --- |
| 1 | `4-7` / 6 | `3-5` / 4 | `2-3` / 2 | `1-1` / 0 |
| 2 | `4-8` / 7 | `3-6` / 5 | `2-4` / 3 | `1-2` / 1 |
| 3 | `5-9` / 8 | `6-11` / 10 | `7-13` / 12 | `8-15` / 14 |
| 4 | `5-10` / 9 | `6-12` / 11 | `7-14` / 13 | `8-16` / 15 |

每个底板模块的上方槽位显示本地接口 `P0–P3`：上 `P3`、右 `P0`、下 `P1`、左 `P2`；下方槽位显示 `P4–P7`：上 `P5`、右 `P6`、下 `P7`、左 `P4`。

界面显示的是模块内本地编号；用于 `highlight_ports` 的协议端口编号仍为全局 `0–63`，计算规则为 `software_slot * 4 + slot_local_port`。

## 界面与交互

### 面板

- 将现有右侧“端口预览”替换为模拟器面板，沿用已确认的白色 ABS 4×4 实物风格槽位和四向端口。
- 面板左侧或顶部提供 9 类积木素材栏，包含中文名称、逻辑符号和端口角色提示。
- 每个槽位展示当前积木名称和角色状态；空槽显示可投放提示。
- 保留模型高亮：后端返回的全局端口号继续点亮对应物理端口，且不影响导线状态。

### 放置积木

- 从素材栏拖拽积木到任意槽位。
- 拖入空槽会放置积木；拖入已占用槽位会替换原积木，并删除涉及旧积木端口的连线。
- 槽位提供移除动作；移除积木同样删除涉及该槽位的连线。
- 每次放置、替换或移除都递增 `topology_revision` 并重新生成快照。

### 连接端口

- 用户先点击一个端口，再点击第二个端口；面板以 SVG 覆盖层画出导线。选择中的首端口有明确强调状态。
- 有效连接必须为物理输出端口到物理输入端口，显示为正常彩色导线，并写入 `valid_links`。
- 输入接输入、输出接输出、输入接输出但方向反向等方向错误显示红线，并以 `error: 3` 写入 `invalid_links`。
- 任一已连接物理端口再次连接时显示红线，并以 `error: 4` 写入 `invalid_links`。
- 未使用的物理端口连线依照固件的 `BOARD_LINK_UNUSED_PORT` 行为显示灰线，不写入 `invalid_links`，也不参与模型电路上下文。
- 点击导线或通过连线列表的删除动作可移除单条导线；清空按钮移除全部积木和导线。

## 状态与快照

浏览器维护单一模拟器状态：16 个软件槽位、导线端点、选中端口和 `topology_revision`。JSON 文本区域只展示由该状态生成的快照，避免手工编辑造成界面与上报数据分叉。

已放置积木的 `slots` 项使用 `slot`、`gate`、`component`、`display_name`、`present`。空槽保留在数组中，但只能使用 `{ "slot": n, "present": false }`；不得带 `unknown`、`gate` 或端口字段。

生成的快照结构遵循固件上报格式：

```json
{
  "schema_version": 2,
  "topology_revision": 7,
  "level": { "level_id": 101, "short_goal": "...", "input_names": "...", "output_names": "...", "input_count": 1, "output_count": 1 },
  "slots": [{ "slot": 0, "gate": 0, "component": "input", "display_name": "输入积木", "present": true }],
  "valid_links": [{ "from_slot": 0, "to_slot": 1 }],
  "invalid_links": [{ "error": 3 }],
  "scan": { "ir_scans": 0, "i2c_scans": 0 }
}
```

为保持与实机完全一致，`valid_links` 不添加浏览器专用端口字段；端口端点只保存在浏览器状态中，用于绘制和校验。HTTP 请求继续使用该快照作为 `circuit`。WebSocket 会话处于 `circuit.snapshot.accepted` 之后时，任何拓扑变更都会自动发送一条新的 `circuit.snapshot`。

## 边界

- 不在浏览器内计算门电路真值或关卡通关结果；后端和实机仍是电路判断的权威。
- 不修改 `CircuitSnapshot` 的后端模型、WebSocket 消息类型或实机固件。
- 本阶段不保存浏览器状态到本地存储，也不实现多根导线的自由拖拽动画；点击两端口是唯一的建线方式。
- 现有模型配置、关卡选择、HTTP 决策、语音 WebSocket、协议日志和 Session 日志看板必须继续可用。

## 验收标准

1. 9 类固件积木都能拖入任意一个 16 槽位。
2. 槽位与端口位置符合映射表，`highlight_ports` 的全局端口高亮正确落到相应物理端口。
3. 有效、方向错误、端口重复和未使用端口连接分别显示正常线、红线、红线、灰线，并生成对应的快照分类。
4. 放置、移除、创建或删除连线后，JSON 中的 `slots`、连线列表和 `topology_revision` 立即更新。
5. HTTP 决策请求和已连接的 WebSocket 会话都使用最新快照；服务器接受的 `topology_revision` 与界面一致。
6. 浏览器无控制台错误，既有测试台功能和端口高亮不回归。
