# 通用电路语义规划器设计

- 日期：2026-08-05
- 状态：已确认设计，待实现计划

## 1. 背景

当前电路助教主要依赖大模型阅读 `circuit_snapshot`，再由后端检查端口角色、占用状态和积木是否解锁。这能阻止明显非法的端口调用，却不能判断一条连线是否符合关卡的布尔逻辑。

第 502 关暴露了这一问题：三块与门已经分别得到三组“两两同时为 1”的结果，但系统仍允许模型把其中一块与门直接连接到最终输出。该连线在物理上合法，在逻辑上却不能覆盖另外两种进位情况。

为该关编写固定阶段规则可以阻止这一错误，但会产生新的问题：

- 每增加或调整一个关卡，都要新增专用判断。
- 容易把某一种搭法误认为唯一正确搭法。
- 无法自然支持儿童已经搭出部分不同但等价的电路。
- 规则文本、端口选择和大模型回复逐渐耦合。
- 遇到错误连线时只能停止，不能准确指导拆线。

因此需要用统一的布尔语义仿真和规划替代按关卡编号编写固定步骤。

## 2. 目标

### 2.1 功能目标

1. 对 101 至 602 的组合逻辑关卡使用同一套分析流程。
2. 根据当前真实积木、有效连线和已解锁积木推导下一步，不按积木数量猜测。
3. 接受不同但布尔功能等价的搭建方式，不限制唯一解。
4. 每轮生成一至三个安全候选动作，由大模型结合用户问题选择。
5. 大模型不再直接生成端口号，端口只由后端从候选动作映射得到。
6. 能识别阻碍完成关卡的错误连线，并用红色高亮提示拆除。
7. 普通聊天和原理解释不强制触发亮灯工具。
8. 规则、搜索或模型异常时保守降级，不执行未经验证的动作。

### 2.2 非目标

- 不在本阶段支持时序电路、反馈存储或模拟电路。
- 不要求搜索全局积木数量最少的唯一最优解。
- 不让大模型参与真值表计算、端口合法性判断或路径安全验证。
- 不改变固件现有的本地关卡判定结果；后端规划只负责助教引导。

## 3. 总体架构

系统拆分为六个边界清晰的组件：

1. **关卡规则仓库 `LevelLogicRegistry`**：后端保存版本化真值表和输入输出定义。
2. **快照规范化器 `CircuitGraphBuilder`**：把固件快照转换为方向明确的电路图。
3. **布尔仿真器 `CircuitSimulator`**：为输入、逻辑门和输出计算真值签名。
4. **语义规划器 `CircuitPlanner`**：搜索多条可完成目标的路线并生成安全动作。
5. **候选动作网关 `SemanticActionGateway`**：向大模型暴露候选编号，隐藏真实端口。
6. **设备工具映射器 `DeviceActionMapper`**：把已选候选转换成连接、摆放或拆线工具调用。

硬约束和自然表达完全分离：语义层决定哪些动作安全，大模型只决定在安全候选中如何选择和解释。

## 4. 后端关卡规则

### 4.1 数据结构

后端仓库中的版本化规则清单是唯一人工维护源。每个关卡规则包含：

```text
LevelLogicSpec
  level_id: int
  rule_version: int
  input_count: int
  output_count: int
  input_labels: tuple[str, ...]
  output_labels: tuple[str, ...]
  expected_outputs: tuple[int, ...]
```

`expected_outputs` 的长度必须等于 `2 ** input_count`。每个整数的低位到高位分别对应排序后的输出积木。

例如三输入、两输出关卡共有八行真值表；若某行个位输出为 1、进位输出为 1，则该行期望值为二进制 `11`，即整数 `3`。

### 4.2 输入输出顺序

后端必须与固件本地判定保持相同顺序：

- 输入积木按 `slot_id` 从小到大映射为输入 0、输入 1、输入 2、输入 3。
- 输出积木按 `slot_id` 从小到大映射为输出位 0、输出位 1、输出位 2、输出位 3。
- 儿童可见名称来自 `input_labels` 和 `output_labels`，不从剧情目标文本推断。

如果未来固件改变输入输出映射方式，应在协议中增加明确的 I/O 映射字段，而不是让后端猜测。

### 4.3 规则版本

固件快照的 `level` 增加：

```json
{
  "id": 502,
  "rule_version": 1
}
```

后端使用 `(level_id, rule_version)` 加载规则。旧设备仍在使用旧规则时，后端可以同时保留多个版本，避免升级期间直接失效。

以下情况禁止语义工具调用：

- 旧快照没有携带 `rule_version`。
- 后端不存在该规则版本。
- 快照的输入输出数量与规则不一致。
- 规则真值表长度或输出位宽非法。

此时普通问答继续工作，并记录包含设备会话、关卡和规则版本的明确异常日志。

## 5. 电路图规范化

`CircuitGraphBuilder` 只使用快照中的真实数据：

- `present` 且身份有效的积木。
- 端口的 `input`、`output` 和 `unused` 角色。
- 状态为 `valid` 的连线。
- `unlocked_gates` 中允许使用的积木。

规范化结果包含：

- 槽位、积木类型和端口索引。
- 方向统一为 `output_port -> input_port` 的边。
- 每个端口当前是否被占用。
- 每个逻辑门的已连接输入和空输入。
- 未识别积木、无效连线、环路和多源输入等诊断信息。

出现未识别积木或无法可靠确定方向的边时，不进行自由接线推荐。结构非法但能够明确定位到现有边时，可生成红色拆线候选。

## 6. 真值签名仿真

### 6.1 表示方式

本项目最多四个输入，因此最多有十六种输入组合。每条信号可表示成一个最多十六位的整数：第 `n` 位表示第 `n` 行输入组合下的输出值。

双输入示例：

- 输入 A 的签名可表示为 `0011`。
- 输入 B 的签名可表示为 `0101`。
- `A XOR B` 的签名为 `0110`。

签名相同即视为功能等价，与使用了哪种门、放在哪个槽位无关。

### 6.2 门运算

仿真器对 `NOT`、`AND`、`OR`、`NAND`、`NOR`、`XOR`、`XNOR` 使用确定性的位运算计算签名。所有结果必须按当前输入数量使用位掩码截断。

输入未接齐的逻辑门不产生完整输出签名，但保留为可复用的部分结构。组合环路不参与正常传播，并进入错误诊断。

### 6.3 输出状态

每个输出被分类为：

- `correct`：已连接信号签名等于目标签名。
- `wrong`：已连接但签名不等于目标。
- `incomplete`：输出没有得到可计算信号。
- `blocked`：结构错误导致无法可靠求值。

会话历史不参与电路事实计算；每次都以最新快照为唯一事实来源。

## 7. 通用语义规划

### 7.1 两阶段规划

规划器分为两层：

1. **功能规划**：从当前已有信号签名和已解锁门类型出发，寻找可得到目标输出签名的逻辑组合。
2. **物理映射**：把逻辑组合映射到当前已有积木、空输入端、空闲输出端和空槽位。

功能规划不绑定槽位，因此可以接受不同的等价表达式。物理映射优先利用儿童已经搭好的正确结构。

### 7.2 搜索方式

使用有界最佳优先搜索：

- 搜索成本按实际儿童操作计数，包括接一条线、放一块积木和拆一条线。
- 状态由当前可用信号签名、部分逻辑门、剩余槽位和输出完成情况组成。
- 相同语义状态进行去重和缓存。
- 搜索不设置固定关卡步骤，也不把积木数量作为完成阶段的依据。
- 搜索边界由剩余槽位、端口和已解锁门自然限制。
- 默认使用可配置的时间和状态数量预算；初始建议为 50 毫秒和 20000 个状态。

搜索超限时返回诊断状态，不返回未经证明安全的端口动作。

### 7.3 候选动作类型

规划器只产生以下动作：

```text
ConnectPorts
  output_port
  input_port

PlaceGate
  slot
  gate

DisconnectPorts
  output_port
  input_port
```

内部候选还应包含：

- `candidate_id`
- 绑定的 `topology_revision`
- 动作前后的语义状态摘要
- 该动作位于多少条可行路线中
- 对儿童解释时可使用的事实
- 排序分数

### 7.4 候选排序

默认优先级为：

1. 把已经得到的正确目标签名接到对应输出。
2. 补完已经摆放且可复用的逻辑门。
3. 选择多条低成本完成路线共有的第一步。
4. 摆放新的已解锁积木。
5. 仅当现有边阻塞所有可行路线时建议拆线。

规划器返回一至三个近似同优先级的安全候选，而不是强制唯一动作。若多个动作只是槽位位置不同，可在物理映射阶段合并，避免让大模型在无意义的位置差异中选择。

### 7.5 多输出关卡

403、504 和 602 等多输出关卡必须联合规划：

- 保留已经正确的输出，不因另一个输出错误而拆除正确部分。
- 鼓励多个输出共享已有中间信号。
- 候选评分同时考虑正确输出数量、剩余操作成本和复用程度。
- 输出位与目标位按规则定义的输出顺序对应。

## 8. 拆线与红色高亮

### 8.1 后端工具协议

现有 `highlight_ports` 增加可选参数：

```json
{
  "output_port": 16,
  "input_port": 2,
  "intent": "connect"
}
```

`intent` 取值：

- `connect`：提示建立一条新连线。
- `disconnect`：提示拆除快照中已经存在的该条连线。

缺少 `intent` 时默认为 `connect`，兼容旧后端响应。

### 8.2 固件行为

- `connect` 使用现有连接提示颜色和动画。
- `disconnect` 必须验证两个端口当前确实构成一条连线，并将两个端口显示为红色。
- 红灯提示期间只表达拆除意图，不能与连接提示共用语音文案。
- `topology_revision` 改变后立即停止旧提示，避免儿童按过期快照操作。

### 8.3 拆线安全规则

拆线候选必须满足以下至少一项：

- 连线结构非法或构成组合环路。
- 该连线让某个输出固定为错误签名，且不存在保留该边的完成路线。
- 该连线占用了完成所有目标所必需的唯一端口。

仅仅因为某条边不属于搜索到的第一条方案，不能建议拆除。

## 9. 大模型交互契约

### 9.1 内部选择工具

大模型不再直接调用设备端口工具。后端向模型提供内部工具：

```json
{
  "name": "choose_circuit_action",
  "arguments": {
    "candidate_id": "rev31-action-2"
  }
}
```

候选编号只在当前请求和当前 `topology_revision` 内有效。

### 9.2 提示内容

模型接收：

- 当前关卡的儿童化目标摘要。
- 当前输出的正确、错误和未完成状态。
- 一至三个安全候选动作的语义原因。
- 用户本轮问题和短期对话历史。

模型不接收可自由组合的候选外端口列表，也不能自行构造新的端口动作。

### 9.3 意图处理

- 普通聊天：自然回答，不强行转回电路。
- 原理解释：解释当前结构或候选动作为什么有帮助，默认不亮灯。
- 明确索取下一步：允许从候选中选择一个动作。
- 明确要求亮灯：选择一个安全候选并执行。
- 询问错误原因：优先解释反例或错误输出；只有用户要求操作时才红灯拆线。

如果模型返回未知候选编号、原始端口号或不支持的工具调用，后端拒绝该调用。明确索取下一步时可使用最高分候选和本地安全中文作为降级；普通聊天时只保留文本回复。

## 10. 设备动作映射

`DeviceActionMapper` 在发送工具前再次验证：

- 候选绑定的 `topology_revision` 与请求一致。
- 连接动作的两个端口仍为空闲、方向正确且不属于同一槽位。
- 拆线动作的两个端口仍构成真实现有边。
- 摆放动作的槽位仍为空，积木仍在 `unlocked_gates` 中。
- 动作仍存在于本轮规划器返回的候选集合。

任何验证失败都不执行工具，并记录候选失效原因。

## 11. 日志与诊断

每次语义规划记录结构化诊断：

- `level_id`、`rule_version`、`topology_revision`
- 规则版本校验结果
- 规范化后的有效边、无效边和环路数量
- 各输出的当前签名和目标签名
- 搜索耗时、访问状态数、完成路线数
- 返回候选及其排序原因
- 模型选择的候选编号
- 最终设备工具调用或拒绝原因

完整原始快照和模型原始输入输出继续进入现有诊断日志，但不得记录 API Key。

## 12. 错误处理与降级

| 场景 | 行为 |
|---|---|
| 规则版本不存在 | 禁用语义工具，普通问答继续，记录规则不匹配 |
| 输入输出数量不一致 | 提醒补齐或检查积木，不运行目标搜索 |
| 存在未识别积木 | 不猜积木功能，说明暂时无法可靠判断 |
| 存在结构非法连线 | 若可定位则提供红色拆线候选 |
| 搜索超时或超限 | 不执行工具，返回保守说明并记录搜索指标 |
| 没有可行完成路线 | 诊断槽位、端口或已解锁积木是否不足 |
| 模型选择未知候选 | 拒绝；明确索取动作时使用本地最高分候选降级 |
| 拓扑版本变化 | 丢弃旧候选，要求基于新快照重新规划 |

## 13. 测试与评测

### 13.1 单元测试

- 穷举验证七种逻辑门的真值签名。
- 验证输入输出槽位排序与固件本地判定一致。
- 验证无效边、反向边、环路、占用端口和未识别积木。
- 验证规则版本匹配和不匹配降级。
- 验证候选编号只能在当前拓扑版本使用。
- 验证拆线候选只指向真实存在的边。

### 13.2 关卡测试

每个关卡至少包含：

- 一种标准正确电路。
- 一种不同但功能等价的正确电路。
- 正确的部分电路。
- 缺少积木或缺少连线的电路。
- 存在一个错误中间连接的电路。
- 已经正确的输出与另一个错误输出并存的多输出电路。

此前真实第 502 关快照作为永久回归样本，禁止再次出现单块与门直连最终进位输出的建议。

### 13.3 跨仓库一致性

后端规则清单是唯一人工维护源，并提供生成工具输出固件使用的 C 规则数组、`rule_version` 常量和规则摘要。生成文件提交到固件仓库，禁止手工修改。

发布或 CI 流程必须重新生成固件规则文件并比较工作区差异。只要后端真值表、输入输出数量或顺序发生变化，就必须提升对应 `rule_version`；未提升版本或生成结果不同均视为失败。

后端测试还要读取同一规则清单，逐关验证用例数量、输出位宽和 `expected_outputs`，避免 Python 运行时结构与规则文件不一致。

### 13.4 并发评测指标

并发评测器新增：

- 语义动作正确率
- 非法端口率
- 错误拆线率
- 正确结构保留率
- 不同等价解继续引导成功率
- 规则不匹配降级率
- 搜索超时率和平均搜索耗时
- 模型候选选择有效率

## 14. 分期实施

### 第一阶段：规则与协议基础

- 建立后端版本化 `LevelLogicRegistry`。
- 为全部现有关卡录入真值表。
- 实现由后端规则生成固件 C 规则数组的工具。
- 固件快照增加 `rule_version`。
- 增加跨仓库规则一致性测试。
- 此阶段不改变现有工具行为。

### 第二阶段：仿真与诊断

- 实现电路图规范化和真值签名仿真。
- 输出结构化电路诊断和输出正确状态。
- 并发评测器记录仿真结果，但暂不让规划器控制工具。

### 第三阶段：连接与摆放规划

- 实现功能搜索、物理映射和候选排序。
- 支持 `ConnectPorts` 和 `PlaceGate`。
- 大模型改为选择候选编号。
- 通用规划器覆盖通过后，删除第 502 关专用 `_plan_level_502` 逻辑。

### 第四阶段：红色拆线

- `highlight_ports` 增加 `intent=disconnect`。
- 固件实现红色端口高亮和拆线提示。
- 规划器增加阻塞路径分析和 `DisconnectPorts`。

### 第五阶段：全关卡切换

- 对全部关卡运行标准解、等价解和错误快照评测。
- 达到验收指标后默认启用通用规划器。
- 保留可配置开关，允许快速回退到纯文本保守模式，不回退到关卡专用硬编码。

## 15. 验收标准

1. 全部现有组合逻辑关卡由统一规则和规划器处理，没有按关卡编号编写的下一步函数。
2. 标准解和等价解均能正确识别并继续引导。
3. 第 502 关真实回归快照不会建议任一单独与门直连最终输出。
4. 大模型无法执行候选集合以外的端口动作。
5. 拆线工具只高亮真实存在的连线，并在固件上显示红色。
6. 正确输出和正确中间结构不会因另一部分错误被无故拆除。
7. 规则不匹配、搜索超时和模型协议错误均安全降级，不产生错误亮灯。
8. 并发评测中非法端口率和错误拆线率为零。
