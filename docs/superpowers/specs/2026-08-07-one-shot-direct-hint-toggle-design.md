# 游玩页一次性“直接提示”开关设计

## 背景

当前游玩页的右键承担所有语音交互：儿童既可能询问下一步，也可能聊天、询问关卡目标或追问原理。后端协议中的 `interaction_intent: "act"` 会在存在安全候选时强制执行动作，因此不能把“按右键”直接映射为 `act`，否则儿童误开开关后询问“你是谁”也可能触发亮灯。

本设计在游玩页面增加一次性触摸开关“直接提示”。开关只表示下一轮语音允许获得具体亮灯提示，不能绕过后端的语义判断、真值表规划和候选校验。

## 目标

- 游玩页面提供可随时触摸的“直接提示”开关。
- 每次进入关卡时默认关闭。
- 开启状态只作用于下一次右键语音请求，请求开始后立即自动关闭。
- 开关开启时，明确的下一步、求助或错误检查请求可以执行一个安全候选。
- 聊天、关卡目标、术语和原理问题即使误开开关也不得调用工具。
- 每轮最多高亮一个空槽或一对端口；拆线提示继续使用红色。
- 保持旧固件和现有文字调试链路兼容。

## 非目标

- 不增加新的实体按键或修改左、中、右键原有行为。
- 不让固件根据关键词决定是否亮灯。
- 不让模型直接生成槽位号或端口号。
- 不把开关状态持久化到 NVS、`sdkconfig` 或跨关卡保存。
- 不在小游戏、关卡树、设置页或剧情引导页显示该开关。

## 用户交互

游玩页固定显示触摸开关：

```text
直接提示  [关闭]
```

状态规则：

1. 进入 `UI_PAGE_PLAY` 时状态为关闭。
2. 点击关闭状态后切换为开启，使用黄色高亮并显示“仅下次语音有效”。
3. 再次点击可主动关闭。
4. 开启后下一次右键开始录音时，固件复制本次状态到语音请求上下文，并立即把屏幕开关恢复为关闭。
5. 请求失败、ASR 无文本、后端拒绝动作或儿童实际在聊天时，开关仍保持关闭；儿童需要时可再次开启。
6. 离开游玩页、返回关卡树、进入成功页或切换关卡时清除开启状态。

立即关闭而不是等待后端响应，可以避免儿童连续按右键时重复携带直接提示许可，也不需要在异步 ASR、后端和 TTS 阶段维护可见开关状态。

## 固件状态设计

`app_ui.c` 保存仅属于当前游玩页的可见状态：

```c
static bool s_direct_hint_armed;
```

游玩页新增 LVGL 可点击对象和标签：

```c
lv_obj_t *play_direct_hint;
lv_obj_t *play_direct_hint_label;
```

触摸回调只切换 `s_direct_hint_armed` 并刷新样式。进入或离开游玩页时统一重置。

语音链路不能在 ASR 完成后重新读取 UI 全局变量，因为儿童可能在录音期间再次触摸开关。右键录音开始时必须原子消费当前值，并保存在本次语音请求的上下文中，例如：

```c
voice_assistant_set_direct_hint_once(s_direct_hint_armed);
s_direct_hint_armed = false;
```

更稳妥的实现可以把一次性值作为 `voice_assistant_update` 的参数传入，并由语音模块在检测到 `press_started` 时锁存；不得在网络任务中直接访问 LVGL 对象。

锁存值随 ASR 文本传入 `assistant_router_submit`，最终只在远程后端请求中使用。内置助教链路可以忽略该值，行为保持不变。

## 协议设计

设备请求新增可选字段：

```json
{
  "user_text": "接下来应该怎么做？",
  "direct_hint_requested": true,
  "circuit_snapshot": {}
}
```

字段语义：

- 缺失或 `false`：保持当前自动路由，优先启发、解释和对话。
- `true`：本轮允许把明确的操作型请求提升为 `act`，但不代表无条件执行。

保留现有 `interaction_intent` 字段以兼容调试器和旧测试：

- `interaction_intent: "auto"` 继续作为设备和普通文字链路的默认值。
- `interaction_intent: "act"` 只用于明确的测试、诊断或未来独立的强制执行入口，不由本开关发送。

后端模型新增：

```python
direct_hint_requested: bool = False
```

并发评测场景的每一轮也支持该字段，以覆盖开关关闭、开启后求助以及开启后聊天误触。

## 后端防误触路由

后端继续先计算真值表规划、诊断和安全候选，再让模型返回结构化路由。`direct_hint_requested` 只改变动作阈值，不改变候选内容。

动作允许条件：

1. `direct_hint_requested` 为 `true`。
2. 用户意图属于下一步、直接求助或当前电路检查。
3. 后端存在未降级且仍适用于当前 `topology_revision` 的安全候选。
4. 候选能够映射为一个合法设备工具。

以下模式必须拒绝工具，即使开关已开启：

| 路由 | 示例 | 行为 |
| --- | --- | --- |
| `chat` | “你是谁？” | 正常聊天 |
| `goal` | “这关要做什么？” | 介绍目标 |
| `explain` | “为什么要这样接？” | 解释原因 |
| `clarify` | “把那个接过去”且指代不唯一 | 请求说明 |

`hint`、`diagnose` 或模型选择的 `act` 只有在本地高置信意图校验也认为用户正在求助、索取下一步或检查电路时，才能提升为执行。该本地校验作为安全闸门，不负责生成答案，也不能选择端口。

如果模型误把聊天判断为 `act`，后端必须撤销动作，仅保留自然文字回复。若没有安全候选、候选过期或工具映射失败，返回说明性文字，不执行本地降级动作。

## 回复风格

开关关闭时：

- 默认给一个观察方向、简单类比或思考问题。
- 不主动公布完整连接，不调用工具。

开关开启且动作获准时：

- 每次只推进一小步。
- 摆放候选只高亮一个槽位。
- 接线候选只高亮一个输出端和一个输入端。
- 拆线候选只高亮一条真实存在的错误线，并使用红色。
- 语音明确说出积木角色和动作，不朗读槽位号或端口号。

## 兼容性

- 旧固件不发送 `direct_hint_requested`，后端按 `false` 处理。
- 新固件连接尚未升级的后端时，额外 JSON 字段可能被严格模型拒绝，因此部署顺序必须是先升级后端，再烧录固件。
- 文字调试链路默认关闭直接提示；测试器可按轮显式开启。
- 学习小游戏暂不显示开关，也不发送该字段。

## 日志与诊断

固件每轮记录：

- 开关是否在录音开始时被消费。
- 提交到远程助教的 `direct_hint_requested` 值。
- 请求编号、关卡编号和最终工具执行结果。

后端 Trace 记录：

- 原始 `direct_hint_requested`。
- 模型原始路由和本地安全闸门结果。
- 动作是否被提升、拒绝以及拒绝原因。
- 最终候选编号、工具映射和 `topology_revision`。

日志禁止记录密钥、Authorization 头或包含凭据的 URL。

## 测试方案

### 后端单元测试

- 开关关闭，询问下一步：允许 `hint`，不强制工具。
- 开关开启，询问下一步：执行首选安全候选。
- 开关开启，要求检查错误连线：执行红色拆线候选。
- 开关开启，询问“你是谁”：禁止工具。
- 开关开启，询问关卡目标：禁止工具。
- 开关开启，追问原理：禁止工具。
- 开关开启但没有候选、候选降级或拓扑过期：禁止工具。
- 模型对聊天错误返回 `act`：本地安全闸门撤销工具。

### 并发模型测试

在 301、403、502、504、601 关分别运行：

- 关闭状态下的循序引导。
- 开启状态下的“接下来怎么做”。
- 开启状态下的“帮我检查哪里错了”。
- 开启状态下的“你是谁”“为什么这样接”。

并发数保持 2，报告保留完整快照、模型原始输入输出、路由、候选和工具调用。

### 固件验证

- 进入游玩页默认关闭。
- 点击后显示黄色开启状态，再次点击关闭。
- 开启后按右键，录音开始时立即恢复关闭。
- 一次请求只携带一次 `true`，下一次请求恢复 `false`。
- 开启后聊天不亮灯，但开关已关闭。
- 退出再进入关卡保持关闭。
- 触摸开关不影响左键返回、中键检查和右键录音。
- 增量构建并烧录，不执行 `fullclean`。

## 部署顺序

1. 后端增加协议字段、安全闸门、测试器支持和自动化测试。
2. 本地并发验证关闭、直接求助和聊天误触场景。
3. 部署后端云端并确认旧固件请求仍正常。
4. 固件增加游玩页开关、一次性锁存和请求字段。
5. 增量编译、烧录并完成实机触摸、语音和亮灯验证。

## 验收标准

- 开关只出现在游玩页，每次进入关卡默认为关闭。
- 开启后只影响下一次右键语音，随后自动关闭。
- 开关关闭时回复保持启发式，不因存在候选自动亮灯。
- 开关开启时，明确操作请求稳定执行一个安全候选。
- 聊天、目标和原理问题在开关开启时仍为零工具调用。
- 所有动作均来自真值表规划器，模型不能编造端口或积木。
- 新旧固件协议兼容，后端升级后旧固件仍能正常使用。
